# Module: auth

## 1. Overview

### 1.1 Name
auth

### 1.2 Description
The Auth module handles user identity management — registration, login, logout, token refresh, and profile retrieval. It implements stateless JWT authentication with refresh token rotation and generates a cache token (HMAC) for Tent cache keying. The module is always-on (loaded at boot) because authentication is required in every session.

### 1.3 Classification

| Type | Value |
|---|---|
| Module Type | always-on |
| Table Prefix | `auth_` |
| Base Route | `/auth` |

### 1.4 Dependencies
- **NestJS packages**: `@nestjs/common`, `@nestjs/jwt`, `@nestjs/typeorm`, `@nestjs/event-emitter`
- **External packages**: `bcrypt`, `class-validator`, `class-transformer`
- **Internal module dependencies**: none (Auth is the first module; others depend on it)
- **Core dependencies**: JwtGuard (Core reads the JWT signed by this module), CacheTokenService (Core uses the HMAC generated by this module)

## 3. API Contract

### 3.1 Endpoints Overview

| Method | Path | Description | Auth Required | Cacheable |
|---|---|---|---|---|
| POST | /auth/register | Create a new user account | NO | NO |
| POST | /auth/login | Authenticate and obtain tokens | NO | NO |
| POST | /auth/refresh | Rotate refresh token and get new tokens | NO | NO |
| POST | /auth/logout | Revoke session and clear cookie | YES | NO |
| GET | /auth/me | Get current user profile | YES | NO |

### 3.2 Endpoint Details

#### POST /auth/register

**Description:** Creates a new user account with email and password.

**Request:**
- **Headers:** none required
- **Body:**

```json
{
  "email": "string (valid email, max 255)",
  "password": "string (min 8, max 72)",
  "name": "string (min 1, max 100)"
}
```

**Response:**
- **Status:** 201
- **Body:**

```json
{
  "id": 42,
  "email": "user@example.com",
  "name": "User Name",
  "role": "user"
}
```

- **Error responses:**

| Status | Condition | Body |
|---|---|---|
| 400 | Invalid email format | `{ "message": "Invalid email format", "code": "INVALID_EMAIL" }` |
| 400 | Password too short | `{ "message": "Password must be at least 8 characters", "code": "WEAK_PASSWORD" }` |
| 409 | Email already registered | `{ "message": "Email already in use", "code": "EMAIL_TAKEN" }` |

#### POST /auth/login

**Description:** Authenticates a user and returns tokens. Sets access token in httpOnly cookie, returns refresh token and cache token in body.

**Request:**
- **Headers:** none required
- **Body:**

```json
{
  "email": "string",
  "password": "string"
}
```

**Response:**
- **Status:** 200
- **Headers:** `Set-Cookie: access_token=; HttpOnly; Secure; SameSite=Lax; Max-Age=900; Path=/`
- **Body:**

```json
{
  "refresh_token": "string (opaque token)",
  "cache_token": "string (HMAC-SHA256 hex)",
  "user": {
    "id": 42,
    "email": "user@example.com",
    "name": "User Name",
    "role": "user"
  }
}
```

- **Error responses:**

| Status | Condition | Body |
|---|---|---|
| 400 | Missing fields | `{ "message": "Email and password are required", "code": "MISSING_CREDENTIALS" }` |
| 401 | Invalid credentials | `{ "message": "Invalid email or password", "code": "INVALID_CREDENTIALS" }` |
| 403 | Account deactivated | `{ "message": "Account is deactivated", "code": "ACCOUNT_INACTIVE" }` |

#### POST /auth/refresh

**Description:** Validates the refresh token, invalidates it (rotation), and issues a new set of tokens. Detects token reuse and revokes the entire session chain if detected.

**Request:**
- **Headers:** none required
- **Body:**

```json
{
  "refresh_token": "string"
}
```

**Response:**
- **Status:** 200
- **Headers:** `Set-Cookie: access_token=; HttpOnly; Secure; SameSite=Lax; Max-Age=900; Path=/`
- **Body:**

```json
{
  "refresh_token": "string (new opaque token)",
  "cache_token": "string (new HMAC-SHA256 hex, different from previous)"
}
```

- **Error responses:**

| Status | Condition | Body |
|---|---|---|
| 400 | Missing refresh_token | `{ "message": "Refresh token is required", "code": "MISSING_REFRESH_TOKEN" }` |
| 401 | Token not found in database | `{ "message": "Invalid refresh token", "code": "INVALID_REFRESH_TOKEN" }` |
| 401 | Token already used (reuse detected) | `{ "message": "Token reuse detected — session revoked", "code": "TOKEN_REUSE_DETECTED" }` |
| 401 | Session revoked | `{ "message": "Session has been revoked", "code": "SESSION_REVOKED" }` |
| 401 | Token expired | `{ "message": "Refresh token expired", "code": "REFRESH_TOKEN_EXPIRED" }` |

#### POST /auth/logout

**Description:** Revokes the current session, clears the access token cookie, and invalidates the refresh token.

**Request:**
- **Headers:**

| Header | Required | Description |
|---|---|---|
| Cookie | YES | httpOnly cookie containing access_token JWT |

- **Body:** none

**Response:**
- **Status:** 200
- **Headers:** `Set-Cookie: access_token=; HttpOnly; Secure; Max-Age=0; Path=/`
- **Body:**

```json
{
  "message": "Logged out successfully"
}
```

- **Error responses:**

| Status | Condition | Body |
|---|---|---|
| 401 | No valid session | `{ "message": "Unauthorized" }` |

#### GET /auth/me

**Description:** Returns the profile of the currently authenticated user.

**Request:**
- **Headers:**

| Header | Required | Description |
|---|---|---|
| Cookie | YES | httpOnly cookie containing access_token JWT |
| X-Cache-Key | YES | HMAC cache token for Tent cache keying |

- **Body:** none

**Response:**
- **Status:** 200
- **Body:**

```json
{
  "id": 42,
  "email": "user@example.com",
  "name": "User Name",
  "role": "user",
  "is_active": true,
  "created_at": "2026-08-23T10:00:00.000Z"
}
```

- **Error responses:**

| Status | Condition | Body |
|---|---|---|
| 401 | No valid token | `{ "message": "Unauthorized" }` |

## 5. Service Interface (Exported Methods)

```typescript
export interface AuthServiceInterface {
  // Validate user credentials and return user entity (without password hash)
  validateUser(email: string, password: string): Promise;

  // Find user by ID (without password hash)
  findById(id: number): Promise;

  // Generate access token JWT for a user
  generateAccessToken(user: AuthUser): string;

  // Generate cache token (HMAC) for a user + session
  generateCacheToken(userId: number, sessionId: string): string;

  // Verify a refresh token and return the associated session (or null if invalid)
  verifyRefreshToken(token: string): Promise;

  // Rotate refresh token: invalidate old, issue new, log the action
  rotateRefreshToken(session: AuthSession): Promise<{ refreshToken: string; sessionId: string }>;

  // Revoke a session by session_id
  revokeSession(sessionId: string): Promise;
}
```

## 6. Business Rules

### 6.1 Validation Rules
- Email must be a valid email format (RFC 5322 simplified)
- Password must be at least 8 characters, max 72 characters (bcrypt limit)
- Name must be at least 1 character, max 100 characters
- Email comparison is case-insensitive
- Email is stored as-is (original case) but looked up case-insensitively

### 6.2 State Transitions

Session state transitions:

```
active -> revoked (trigger: logout)
active -> revoked (trigger: token reuse detected)
active -> expired (trigger: expires_at passed, lazy check on next refresh)
```

Token lifecycle:

```
issued -> used (trigger: successful refresh rotation)
issued -> revoked (trigger: session revoked)
used -> reused_detected (trigger: same token presented again after rotation)
```

### 6.3 Access Control

| Role | Permissions |
|---|---|
| user | Can manage own account, own sessions, own data |
| admin | Can manage own account + view all users (future) |

All endpoints enforce user isolation — a user can only access their own sessions and profile.

### 6.4 Constraints
- One active session per refresh token — rotation invalidates the previous token immediately
- Token reuse detection: if a refresh token that was already rotated is presented again, the entire session chain is revoked and logged as `reused_detected`
- Refresh token expiry is checked both in the database (`expires_at`) and via JWT claims
- A deactivated user (`is_active = 0`) cannot login or refresh tokens
- Password hashes use bcrypt with cost factor 10

## 7. Security Considerations

### 7.1 Data Sensitivity

| Field | Sensitivity | Encryption at Rest | Notes |
|---|---|---|---|
| password_hash | HIGH | YES (bcrypt) | Never selected in queries by default (select: false) |
| refresh_token_hash | HIGH | YES (bcrypt) | Stored as hash, never plaintext |
| email | MEDIUM | NO | Used for login, unique |
| session_id | MEDIUM | NO | UUID v4, used for cache token HMAC |
| role | LOW | NO | Authorization decision |
| cache_token | LOW | NO (HMAC) | Not stored — generated on demand, not an auth credential |

### 7.2 Required Guards

| Endpoint | Guard | Notes |
|---|---|---|
| POST /auth/register | none | Public endpoint |
| POST /auth/login | none | Public endpoint |
| POST /auth/refresh | none | Uses refresh token in body instead of JWT |
| POST /auth/logout | JwtGuard | Requires valid access token in cookie |
| GET /auth/me | JwtGuard | Requires valid access token in cookie |

### 7.3 Rate Limiting

Recommended rate limits for auth endpoints (to be implemented at the NestJS level or via Tent):

| Endpoint | Limit |
|---|---|
| POST /auth/login | 5 requests per minute per IP |
| POST /auth/register | 3 requests per minute per IP |
| POST /auth/refresh | 10 requests per minute per IP |

## 8. Testing Requirements

### 8.1 Unit Tests
- `AuthService.validateUser()` — correct password, wrong password, deactivated user, non-existent email
- `AuthService.generateAccessToken()` — token contains correct payload (userId, role), correct expiry
- `AuthService.generateCacheToken()` — deterministic for same input, different for different sessionId
- `AuthService.verifyRefreshToken()` — valid token, expired token, revoked session, non-existent token
- `AuthService.rotateRefreshToken()` — old token invalidated, new token issued, log entry created
- `AuthService.revokeSession()` — session marked as revoked, refresh token log updated
- Token reuse detection — presenting an already-rotated token triggers revocation of the chain

### 8.2 E2E Tests
- Register -> Login -> Access protected endpoint -> Refresh -> Access protected endpoint -> Logout
- Register with duplicate email -> 409
- Login with wrong password -> 401
- Refresh with expired token -> 401
- Refresh with already-used token -> 401 + session revoked
- Logout without valid token -> 401
- GET /auth/me without cookie -> 401

- Test admin: `admin@example.com` / `AdminPassword123!` / name: `Admin User`
- Use bcrypt with cost factor 4 in tests (faster) vs 10 in production

## 10. Implementation Notes

The Auth module is always-on and registered directly in the imports array of `AppModule`:

        signOptions: { expiresIn: '15m' },

  providers: [AuthService],
  exports: [AuthService, JwtModule],

### 10.3 Known Limitations
- Token reuse detection is eventual — if two concurrent requests use the same refresh token simultaneously, both might succeed before the database is updated. This is mitigated by using database-level row locking during rotation.
- The cache_token rotates on every refresh, which means the Tent cache is invalidated for the user after each token refresh. This is acceptable given the low traffic and single-user sessions.
- There is no email verification flow — users can register with any email format. This is acceptable for the current scale but should be added before opening registration to the public.

### 10.4 Future Considerations
- Email verification via SMTP or transactional email service
- Password reset flow via email
- Two-factor authentication (TOTP)
- Session listing and management UI (view active sessions, revoke remotely)
- OAuth2 / social login (Google, GitHub)
- Rate limiting at the NestJS level using `@nestjs/throttler`
