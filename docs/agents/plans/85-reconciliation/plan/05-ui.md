# UI specs

Write two UI files based on the issue's *UI workflow* section. Both anchor the decisions to the
existing shared components found by the frontend exploration (paths under
`frontend/assets/js/components/resources/bank/common/`, `B/` below). Everything lands in the
shared `bank/common` detail, so all four account types get it without per-type copies.

**`docs/agents/specs/reconciliation/ui/reconcile.md`** — entry point, start form, reconcile
mode:

- **Entry point** — a **Reconcile** button in the `B/detail/helpers/AccountHeaderHelper.jsx`
  actions row (next to Edit / Archive), as a private `renderReconcileButton` that returns null
  when archived or not allowed. It reads **Continue reconciliation** when
  `open_reconciliation_id` is set.
- **Role gating** — a new `ACTIONS.RECONCILE` (and `ACTIONS.UNDO_RECONCILIATION`) in
  `frontend/assets/js/utils/permissions/orgPermissions.js` with `MIN_ROLE` rows matching the
  backend's (provisional) minimum roles, read through `useCan`.
- **Start / Edit statement form** — **Statement date** (defaults to today, with `max` today
  like the ledger form) and **Statement balance** (`B/form/AccountFormInput.jsx` with
  `inputMode: 'decimal'`, parsed with `B/amounts.js` `parseAmount`). On a debt it is labelled
  "Amount owed" and negated with `negateAmount` on load and on submit, the same as
  `debts/pages/controllers/debtFormFields.js`.
- **Reconcile mode** — on the same detail page, rendered through the `renderAfterHeader` slot
  of `B/detail/helpers/AccountDetailHelper.jsx`:
  - a sticky **summary bar** showing statement date, statement balance, cleared balance and
    **Difference** (highlighted unless 0), with the actions **Finish** (enabled only at 0),
    **Edit statement** and **Cancel** (Cancel opens `B/ConfirmModal.jsx`);
  - a **checkbox column** in `B/detail/helpers/LedgerTableHelper.jsx`, enabled only on eligible
    rows (≥ `opening_date`, ≤ `statement_date`, not cleared by an earlier statement).
    Ineligible rows are dimmed, and the opening row has no checkbox;
  - **Show only uncleared** — a local filter on the loaded page, independent of #90;
  - **Tick all on page / Untick all** — one call to the bulk ticks route;
  - **Optimistic toggle** — flip the checkbox, call `PATCH …/ticks.json`, take the difference
    from the response, and revert on error;
  - the inline transaction form stays usable, so a new transaction can be added and then
    ticked.
- **Client** — new methods in `frontend/assets/js/client/BankClient.js` (or a new
  `ReconciliationsClient.js` spread into it, like `TypedAccountsClient.js`): `listReconciliations`,
  `startReconciliation`, `getReconciliation`, `updateReconciliation`, `cancelReconciliation`,
  `tickTransactions`, `finishReconciliation`, `undoReconciliation`. Each body is whitelisted.

**`docs/agents/specs/reconciliation/ui/ledger.md`** — normal ledger, header and history:

- **Cleared marker** — a "✓ cleared" marker on rows with `reconciliation.status ===
  'finished'` (tooltip with the statement date, formatted in the display locale), through
  `renderRowExtra` or a dedicated cell.
- **Locked fields** — for a cleared row, the inline form in `B/detail/helpers/LedgerFormHelper.jsx`
  / `ledgerFormFields.js` renders `amount` and `date` read-only, and `renderDelete` in
  `LedgerTableHelper` returns null. The server's 409 stays the backstop.
- **Warning badge** — on an uncleared row dated ≤ `last_reconciled_date`: "Not on reconciled
  statement of <date>".
- **Header line** — "Last reconciled: <date> · <balance>" under the `Balance:` line in
  `AccountHeaderHelper`, from `last_reconciliation`. On a debt the balance is shown negated.
- **Statements history** — a section rendered for every type from the shared
  `AccountDetailHelper` (not per section page). Modelled on Bill history
  (`B/bills/BillHistory.jsx`, `hooks/useBillHistory.js`, `controllers/BillHistoryController.js`,
  `helpers/BillHistoryHelper.jsx`, `B/BankPagination.jsx`): date, balance, `reconciled_at`,
  row count, newest first, paginated in component state. **Undo** appears only where
  `undoable` and allowed, behind a confirmation modal like `B/bills/UndoPaymentConfirm.jsx`.
- **Errors** — through `B/BankErrorAlert.jsx` / `B/bankErrors.js` `classifyError`, with a new
  code → message `Map` for `RECONCILIATION_UNBALANCED`, `RECONCILIATION_OPEN`,
  `RECONCILIATION_OUT_OF_ORDER`, `RECONCILIATION_NOT_LATEST`, `RECONCILIATION_FINISHED`,
  `TRANSACTION_NOT_ELIGIBLE`, `TRANSACTION_CLEARED` and `ACCOUNT_RECONCILED`. Record that
  there is no central code map today, and decide that this one lives next to the
  reconciliation controller.
- The account edit form shows the opening fields read-only when `last_reconciliation` is set,
  with a hint to undo the statements first.

**Required tests** — Jasmine specs mirroring the source paths under
`frontend/specs/assets/js/...`: header button states (archived, role, open), the debt
negation, the optimistic tick revert, Finish disabled unless the difference is 0, the cleared
marker and locked fields, the warning badge, history Undo visibility, and the error messages.
