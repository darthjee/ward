# Write the UI specs

Transcribe the epic's UI section, consistent with `docs/agents/modules/bank/ui.md` and
`docs/agents/architecture/frontend.md` (router tables in
`frontend/assets/js/utils/routing/routes.js`, section registry, context in the URL — **not**
`frontend/app/routing/`, which does not exist).

**`ui/provider-bills.md`**

- Provider detail **Bills** block: one row per bill — description, kind badge, expected amount
  with frequency, due day / month; no balance; actions Add bill, Edit, Delete, History link.
- Add / edit bill (`<ui>/bills/new?provider=:id`, `<ui>/bills/:billId/edit`, routes reused):
  `kind` selector disabled on edit; field sets per kind; server errors mapped to messages.
- Provider list column: "3 bills · R$ 250,00/mo + R$ 1.200,00/yr" rules (zero part omitted,
  recurring without `expected_amount` counts toward N only, one-offs excluded from sums, `—`
  with no bills).
- Per-bill history page listing only that bill's payments.
- Which routes are added to the context-aware route tables (personal and org).
- Reference; Required tests (Jasmine specs under `frontend/specs/` for the Bills block, the
  disabled `kind` selector, the list-column formatter, the history page).

**`ui/calendar.md`**

- Calendar entry primary label `source_bill.description`, secondary the provider name
  ("Internet / Vivo"); debt entries unchanged.
- Pay form reads `source_bill` and targets the per-bill payment route; accepts both `provider`
  and `provider_bill` in `CHARGE_KINDS` (`frontend/assets/js/client/CalendarClient.js`,
  `calendar/common/PayForm.jsx`); amount required when `expected_amount` is `null`.
- Reference; Required tests (label rendering, Pay form route selection, both charge kinds).
